Q22 — Reproducible Processor Benchmark

Advanced3–5 hQPU optional

Scientific objective: Design a controlled, metadata-rich backend experiment.

Prerequisite reading: Chapter 12 — Benchmarking and Reproducible Quantum Experiments.

Before you code

  1. Write the state, operation, Hamiltonian, or protocol quantity relevant to this experiment.
  2. Write a qualitative prediction.
  3. Define the metric you will use to decide whether the prediction was supported.

Baseline experiment

Define a circuit family and metric before execution. Preserve backend/date/shots/compilation/raw counts and discuss drift and limitations.

Step-by-step workflow

  1. Create projects/q22-yourgithubname/.
  2. Write the hypothesis in README.md before running.
  3. Implement the smallest baseline in notebook.ipynb.
  4. Run the simulator baseline and save raw counts/data.
  5. Calculate the required metric numerically; do not rely only on visual inspection.
  6. Create at least one labeled figure or table.
  7. Change exactly one primary experimental variable for the extension.
  8. Repeat the measurement with all other controls fixed.
  9. Explain agreement, disagreement, uncertainty, and limitations in REPORT.md.

Time and execution estimate

Student work: 3–5 h. Execution: QPU optional. Simulator runtime is normally a small fraction of student working time for these teaching-scale examples. QPU queue and cost are provider-dependent and must be recorded rather than guessed.

Optional qBraid/QUEST execution pathway. OQCL is independent of qBraid. If your instructor has provisioned QUEST/qBraid access, the approved hardware portion may be executed there. qBraid describes its education environment as providing preconfigured student environments, real-hardware homework, provisioned access, and class spend controls; QUEST provides participating courses access to multiple QPUs. Follow current official documentation and your instructor's budget rules. See References.

Research extension

Propose one controlled extension that changes a scientifically meaningful variable. State the prediction before execution. A failed prediction is acceptable when the experiment is reproducible and the analysis is sound.

Submission

Apply by email and wait for instructor approval before beginning graded work. Submit the completed folder through a Pull Request and complete the repository checklist.

Project Guide: Q22

Scientific goal: Reproducible processor benchmark.

QUEST supplementary reading: Review Quantum hardware benchmarking in the official qBraid QUEST resources or in the corresponding activity in your QUEST course workspace, if available. This is a topic recommendation, not a claim that QUEST hosts a public notebook for this exact project.

  1. Read the prerequisite OQCL chapter and write a testable hypothesis.
  2. Complete the baseline simulation and save code, parameters, and raw measurements.
  3. Run a fixed test suite with backend metadata and raw result preservation.
  4. If hardware is relevant, obtain instructor approval and follow the official QUEST instructions.
  5. Analyze the discrepancy, uncertainty, and limitations; submit reproducible figures and a short report.

Deliverables: hypothesis, runnable notebook, raw results, labeled plot or table, execution metadata, and scientific interpretation.

Apply: Email saghiria@wpunj.edu with Q22 — Reproducible processor benchmark, your name, and a short proposal. Wait for approval before beginning graded or QPU work.
