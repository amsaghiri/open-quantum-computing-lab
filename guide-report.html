Guide 2 — Writing README.md and REPORT.md

About 15 minutes to readTemplates included

Every project needs two short text files. The README lets someone else rerun your work. The REPORT explains what the result means. Copy the templates below and fill them in.

Where to get the files. Both templates are in the templates folder of the repository, ready to copy into your project folder.

README.md — so others can reproduce your work

Write the Question, Hypothesis, and Metric sections before you run anything. Fill in the rest when you finish.

# Qxx — Project title

**Student / team:**
**GitHub username(s):**
**Date:**

## Question
What scientific question does this experiment answer? (1–2 sentences)

## Hypothesis
What do you predict will happen, and why? Write this BEFORE you run anything.

## Metric
What number will you compute to decide whether the prediction was supported?

## How to reproduce
1. Install the dependencies: `pip install -r environment/requirements.txt`
2. Open `notebook.ipynb` and run all cells from top to bottom.
3. Raw data is written to `results/raw/` and figures to `results/figures/`.

REPORT.md — what the result means

# Qxx — Project title: Report

## 1. Baseline
What did you reproduce? State the prediction you wrote before running, then the measured result (give the metric as a number, not only a figure).

## 2. Extension
Which single primary variable did you change? What stayed fixed? What did you predict?

## 3. Results
Tables and labeled figures (stored in `results/figures/`). Report the metric for the baseline and for the extension.

## 4. Interpretation
Did the results support the prediction? Separate three possible sources of any difference:
1. the ideal mathematical prediction,
2. finite-shot sampling,
3. implementation effects such as noise or compilation.

## 5. Uncertainty
How large is the sampling uncertainty? How do you know (repeated runs, shot count, error estimate)?

## 6. Limitations
What can this experiment NOT tell us? What would you change with more time or resources?

## 7. Conclusion
Two or three sentences: what you learned and what evidence supports it.

## Sources
List every third-party source, tutorial, or code you used.

What a good answer looks like

SectionWeakStrong
Hypothesis“I think it will work.”“P(0) will be within 0.05 of 0.5 at 1,000 shots, because the ideal probability is ½.”
ResultsA screenshot of a histogram.A table of counts, the metric as a number, and a labeled figure made from the saved data.
ExtensionSeveral things changed at once.One variable changed, the others listed as fixed.
Interpretation“The result was close.”“The remaining difference of 0.014 is consistent with sampling error at 1,000 shots.”
LimitationsLeft empty.“A simulator has no hardware noise, so this says nothing about a real device.”

Explaining a difference between prediction and result

When your measurement does not match the ideal value, decide which of three layers can explain it:

  1. The ideal mathematical prediction — was the calculation itself right?
  2. Finite-shot sampling — is the difference the size you expect from randomness?
  3. Implementation effects — noise or compilation, when you use a noisy simulator or real hardware.

Final checklist

This is the same checklist you confirm when you open your Pull Request.

  • README reproduces the work
  • Notebook is executable, or its limitations are documented
  • Raw data included
  • Figures labeled
  • REPORT interprets uncertainty and limitations
  • Dependencies documented
  • No secrets or private information
  • Third-party sources and code cited
